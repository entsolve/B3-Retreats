# B³ Retreats — лендинг (локальный прототип)

Статичный сайт: HTML + CSS + один файл JS. Без сборки, без npm, без внешних запросов.
Язык страницы — немецкий (`lang="de"`), целевая аудитория — DACH.

```
index.html            лендинг — генерируется, руками не править
impressum.html        ┐
datenschutz.html      ├ генерируются из tools/content/ — руками не править
agb.html              ┘
content/site.json     ВЕСЬ текст лендинга: заголовки, абзацы, цены, фото, SEO
admin/                редакторская панель (index.html + admin.css + admin.js + schema.json)
assets/
  css/style.css       вся вёрстка
  css/fonts.css       @font-face (генерируется)
  fonts/*.woff2       Cormorant Garamond + Manrope, локально (297 КБ)
  js/main.js          ссылка на оплату, меню, «наверх», куки-баннер, появление блоков
  img/*.webp          31 обработанное фото
tools/
  templates/index.html  вёрстка лендинга с плейсхолдерами

  admin-server.py       локальный сервер редакторской панели

```

## Запуск

```bash

python3 -c "from http.server import SimpleHTTPRequestHandler, ThreadingHTTPServer; ThreadingHTTPServer(('127.0.0.1', 8788), SimpleHTTPRequestHandler).serve_forever()"
```

Открыть <http://localhost:8788/>.

Именно `ThreadingHTTPServer`, а не `python3 -m http.server`: однопоточный сервер

Открывать `index.html` двойным кликом (`file://`) тоже можно, но шрифты в этом
режиме заблокирует CORS.

### Почему JSON, а не база данных

Сайт статический и разворачивается как набор файлов. SQL здесь дал бы бэкенд в
проде, миграции и поверхность атаки — ради одного редактора. `content/site.json`
лежит в git: каждая правка видна в диффе, откат — обычный `git revert`, никакого
сервера на боевой машине. Сервер нужен только на время редактирования и слушает
исключительно `127.0.0.1`.

### Как устроен обратный путь

`tools/templates/index.html` — это тот же лендинг, но значения заменены на
плейсхолдеры. Язык шаблона знает ровно три конструкции:

```
{{ путь.к.значению }}
{{# путь.к.списку }} … {{/ путь.к.списку }}     повтор, внутри {{ .поле }}
{{? путь.к.значению }} … {{/? путь.к.значению }} только если заполнено
```

Ключевая гарантия — **побайтовое совпадение**:

```bash
python3 tools/build-site.py --check
```

Собирает страницу из JSON и сравнивает с тем, что лежит на диске. Пока эта
проверка зелёная, шаблон ничего не потерял и не переписал. Гонять после любой
правки шаблона.

### Значения хранятся HTML-готовыми

В `site.json` лежит `Be free to be&nbsp;you.` — с сущностью, а не с символом.
Панель показывает её расшифрованной, а при сохранении маскирует обратно, но
**только если текст реально меняли**. Иначе нетронутое поле сменило бы написание
(в вёрстке вперемешку `&ndash;` и сам символ) — и `--check` перестал бы сходиться.

### Что можно добавлять и удалять, а что только править

Списки с кнопкой «Eintrag hinzufügen» — 19 штук: FAQ, тайминг, состав пакетов,
Experiences, абзацы внутри них. **Нельзя** добавлять записи в двух местах, и это
осознанно:

- `ort.mosaic` — 8 слотов мозаики с фиксированными классами `m1`…`m8` и
  пропорциями в CSS; девятая плитка потребовала бы правки вёрстки;
- `team` — три основательницы заданы по именам (`sophie`, `sarah`, `christina`),
  у Сары нет строки-акцента. Тексты и фото правятся, состав — нет.

### Фото

Загруженное фото прогоняется через тот же грейд, что и `build-assets.py`:
блики, тёплый баланс, гашение синевы неба, зерно, виньетка. Без этого шага снимок
выпадет из тональности — небо на исходниках кобальтовое. Проверено: RGB(60,110,230)
на входе → (163,184,207) на выходе. Роль («Außen», «Porträt», …) выбирает профиль
грейда; портреты не трогают красный канал, иначе на коже пятна.

### Сохранения

Перед каждой записью сервер копирует `site.json` в `content/backups/`. Имена
дополняются счётчиком: откат сначала сохраняет текущее состояние и пишет уже в ту
же секунду — без счётчика второй файл затирал бы первый, и «откат» возвращал бы
ровно то, от чего уходили. Хранится 40 последних, папка вне git.

## Ссылка на оплату

Живёт в панели, поле **«16 Buchung → Buchungslink»** (`buchung.url`). Одну ссылку
Tentary подхватывают все 9 кнопок на странице — `target="_blank"`,
`rel="noopener noreferrer"`.

Раньше это была константа `BOOKING_URL` в `assets/js/main.js`, и заказчица
не могла поставить самое важное значение сайта без правки JavaScript.

Нужны разные ссылки на тарифы — есть два необязательных поля в разделе
**«12 Unterkunft und Preise»**: `haus.shared.url` и `haus.friends.url`. Заполнено —
действует для своей кнопки, пусто — снова берётся общая ссылка.

Как это доезжает до кнопки: шаблон пишет адреса в `data-booking-url` на `<body>`
и на сами кнопки тарифов, `main.js` их оттуда читает. Пока ни одна ссылка не
задана, кнопка остаётся на своей цели из шаблона (`#buchung`, на правовых
страницах `/#buchung`) — то есть даже пустое состояние куда-то ведёт.

## Куки-баннер

Сейчас страница **не ставит ни одной куки** и не грузит ничего с чужих серверов —
шрифты локальные, карты нет, виджетов нет. По § 25 TDDDG баннер в таком виде
юридически не обязателен, но он собран так, чтобы работать в тот момент, когда
появится первый счётчик.

Как устроено:

- две настоящие кнопки — «Nur notwendige» и «Alle akzeptieren», без тёмных паттернов;
- выбор пишется в `localStorage` под ключом `b3-consent`, больше ничего не сохраняется;
- страница не блокируется — оверлея и модалки нет, потому что блокировать нечего;
- переоткрыть можно из футера, ссылка «Cookie-Einstellungen» есть на всех страницах;
- всё описано в Datenschutz, раздел 10.

Когда появится аналитика или пиксель, подключать его надо **только** внутри
`loadOptional()` в [assets/js/main.js](assets/js/main.js) — тогда он загрузится
исключительно после «Alle akzeptieren». Проверить статус из другого скрипта:
`window.b3Consent.optionalAllowed()`.

## Пересборка ассетов

```bash
python3 tools/build-fonts.py    # шрифты с Google Fonts → локальные woff2 + fonts.css
python3 tools/build-assets.py   # фото из «materials- in» → assets/img/*.webp
python3 tools/build-legal.py    # tools/content/*.{md,txt} → impressum/datenschutz/agb
```

`build-assets.py` — не просто ресайз. Фото сняты в жёсткий полдень, небо
кобальтовое, вид «объявление о недвижимости». Скрипт по очереди: применяет
EXIF-поворот (26 файлов лежали боком), убирает пересветы, греет баланс белого,
выборочно гасит синеву неба (`S ×0.42`), уводит зелень в оливу, поднимает чёрную
точку до тёплой, добавляет зерно и тёплую виньетку. Грейд запекается в файлы —
глобальный CSS `saturate()` вместе с небом убил бы золото полей и телесные тона.

Правки кропов — в списке `JOBS` внизу скрипта.

### `?v=` — почему без этого правки «не видны»

Имена файлов не меняются: после пересборки `assets/img/hero-tall.webp`
называется так же, и браузер отдаёт свою старую копию — тот же адрес, другое
содержимое. На согласовании это стоило целого круга («ты картинку не поменял»),
причём молча: и CSS тоже был старый, так что правки вёрстки тоже не доходили.

Поэтому `build-site.py` дописывает к каждой локальной ссылке на `.webp`, `.css`,
`.js` и `.woff2` строку `?v=` с первыми восемью знаками хэша содержимого.
Содержимое то же — адрес тот же, кэш работает как раньше; содержимое другое —
адрес другой, браузер грузит заново. `--check` при этом остаётся зелёным.

Важное следствие: **после `build-assets.py` надо запускать `build-site.py`** —
иначе в HTML останется старый хэш.

### Розовый цвет hero: две оси, а не одна

Первый подход к этой проблеме был мимо, и ошибка поучительная. Цветовой сдвиг
живёт на **двух** осях:

```
R−B            тепло  ←→  холод
G−(R+B)/2      зелень ←→  магента
```

Розовый — это вторая ось. Первая правка меряла только `R−B`, то есть теплоту, —
а с теплотой у кадра всё было в порядке. По второй оси:

| | `G−(R+B)/2` |
|---|---|
| настоящие фото заказчицы | **+0,012 … +0,023** |
| исходники hero | **−0,059 … −0,072** |

Почти 0,08 разницы: кадру не хватает зелёного, и именно это видно как розовая
плёнка на траве, коже и небе. Сдвиг сидит в самом исходнике, не в грейде —
у `out/_verworfen/vor-umarmung-tall.png` он уже −0,070.

`tools/hero-drei/farbe-angleichen.py` считает три канальных коэффициента из трёх
условий: убрать сдвиг по магента-оси, **сохранить** `R−B` (теплота кадра нужна)
и сохранить яркость. Для высокого кадра выходит зелёный +13 %, красный −5 %,
синий −6 %. После этого обе оси совпадают с настоящими фото: `R−B` +0,103 против
+0,086, магента-ось +0,016 против +0,021.

Вывод на будущее: одной метрики для цвета не хватает. Если картинка «розовая», а
`R−B` в норме — смотреть надо на `G−(R+B)/2`.

### Трава: это была не краска, а резкость

Заказчица назвала передний план «как в сказке ужасного качества», и она права:
все стебли одного размера, в одну сторону, повсюду одинаковые светлые ниточки,
ни земли, ни разных растений, ни глубины.

Причина нашлась в истории промтов. Самый первый (`prompt.txt`) описывал передний
план **правильно**:

> a couple of blades of grass crossing the very front of the frame, **soft and
> out of focus**

Потом `fix11.txt` потребовал ровно обратного — каждый стебель резко, «fine seed
hairs and awns catch the low sun as **separate bright lines**». Это и есть
гравюра.

Промтом это не откатывается: модель перерисовывает площадь при каждом проходе и
каждый раз её снова подшарпливает (замерено — градиентная энергия росла в
**каждом** проходе, как бы прямо промт это ни запрещал).

Оптически это и не задача рисования, а задача объектива. На 85 mm f/2.8 с
фокусом на женщинах трава в метре от камеры физически вне зоны резкости.
`tools/hero-drei/tiefenschaerfe.py` считает эту нерезкость детерминированно:
мягкий градиент снизу (`--start`, ниже ступней) и по левому краю с чертополохом,
два уровня размытия, чтобы середина градиента получала настоящую половинную
нерезкость. Градиентная энергия внизу кадра: 17 → 6,7.

### Профиль `hero_klar` — почему у айфмакера свой грейд

Тёплые ручки скрипта складываются: баланс белого гонит красный вверх и синий
вниз, `matte()` поднимает точку белого до слоновой кости, `halation()` кладёт
тёплый ореол вокруг светлых краёв, небо разбеливается на `V ×1.08`. На фото
интерьера это незаметно. На аймейкере, где неба треть кадра, всё это сходится в
розовую плёнку поверх всей картинки — и снимок читается как «с фильтром», а не
как фотография. Заказчица так и сказала.

`hero_klar` отпускает ровно эти четыре ручки (числа и причины — в комментарии у
профиля) и оставляет зерно, микрошарп и хроматическую аберрацию: именно они
дают фактуру и следы объектива, по которым кадр читается как съёмка. После
правки `R−B` аймейкера +0,102 против +0,086 у настоящих фото заказчицы — раньше
было +0,164.

Квер и хох — две отдельные генерации. Чтобы на телефоне не
было теплее, чем на десктопе, широкий кадр сперва подтянут к высокому по `R−B`,
и только потом снят магента-сдвиг — оба шага до грейда.

### Форма фотоблоков: свес за край + овал к тексту

Один и тот же приём на четырёх секциях, направление чередуется:

| Секция | Свес | Овал |
|---|---|---|
| Аймейкер (`.hero__ph`) | вправо | слева |
| «Wann hast du dir…» (`.invite__ph`) | вправо | слева |
| Experiences (`.exp__item`) | влево / вправо через один | справа / слева |
| Унтеркунфт, слайдер (`.tier__ph`) | влево | справа |
| «Ist B³ für dich?» (`.fuerwen__ph`) | вправо | слева |

Три вещи, которые тут неочевидны:

* **Радиус по горизонтали считается от ширины, по вертикали — от высоты.** У
  портретных 4:5 работает `42% / 50%`; у слайдера 3:2 те же 42 % дают не дугу, а
  форму листа — там стоит 18 %.
* **Секции нужен `overflow: hidden` и свой `--bleed`**, иначе `100vw` вместе с
  шириной скроллбара даёт горизонтальную прокрутку.
* **Свес — только для картинки.** Подпись слайдера и полоски прогресса лежат
  внутри `.galerie`, поэтому у них `padding-left: var(--bleed)` — иначе текст
  уезжает за край окна.

На ≤860 px всё это снимается: блоки складываются в столбик, край окна больше не
рядом, и овал стал бы просто косым углом.

## Чего на странице сознательно нет

Ни одной тени, ни `backdrop-filter`, ни `rgba(0,0,0,…)`, ни эмодзи, ни готовых
иконок. Скругления только два: окружность (медальон, фазы луны, кнопка «наверх») и
арка для портретов и интерьеров. Разделяют блоки три вещи — волосяная линия,
смена тона фона и воздух.

Внешних запросов нет вообще: шрифты локальные, карта — контурный SVG, никаких
Google Maps, ленты Instagram и виджетов. Именно поэтому куки-баннер здесь
информирует, а не блокирует — блокировать пока нечего.

## Анимация

Правило: движение работает как в печати, а не как в веб-шаблоне. Ни пружин, ни
поворотов, ни счётчиков, ни fade-up на каждом элементе подряд.

| Приём | Где | Как |
|---|---|---|
| Раскрытие строк из-под маски | все крупные заголовки Cormorant | JS режет текст на реальные строки, каждая едет вверх из `overflow:hidden`, шаг 75 мс |
| Шторка на фото | все `.ph`, кроме арок и фонов | `clip-path` открывается снизу за 1,4 с, картинка одновременно едет с 1.1 к 1 — две скорости, поэтому похоже на камеру |
| Прорисовка линеек | `.ruler`, подчёркивание над `.eyebrow` | `scaleX` от левого края |
| Строки списков | Was ist inklusive, Ist B³ für dich, FAQ, таймлайн, удобства | шаг 55 мс, только внутри одного списка |
| Фазы луны | разделители | круги появляются по очереди |
| Параллакс | герой, фризы, фоны бронирования и финала | ±7–9 % высоты, одна rAF-петля, только `transform` |
| Полоса чтения | 1 px тауп сверху | тот же приём, что и волосяная линия |
| Заливка кнопки | все `.btn` | шторка снизу вместо скачка цвета |
| Меню | мобильная панель | пункты въезжают по очереди, 55 мс |
| FAQ | аккордеон | закрытие тоже плавное — нативный `<details>` этого не умеет, перехвачено в JS |

Замерено: 98 кадров/с при прокрутке всей страницы, CLS = 0.

Осторожно с селекторами появления. Контейнер, который сам получает `.is-in`,
нельзя адресовать как `.is-in .liste li` — это требует, чтобы список лежал
*внутри* появляющегося элемента, а он им и является. Строки тогда остаются
невидимыми навсегда. Поэтому контейнеры помечаются классом `.stagger`, а правило
покрывает оба случая: `.stagger.is-in > *` и `.is-in .stagger > *`.
При `prefers-reduced-motion: reduce` выключается всё, включая разрезание строк —
заголовки остаются цельным текстом.

## Дефицит фотографий

Не закрывать стоком — сломается вся тональность. Не хватает:

- кадра под сессию Кристины «Struktur» — сейчас стоит скамья на террасе,
